# AngioEye 1.24.1: EyeFlow compatibility

Community build based on DigitalHolography/AngioEye v1.24.0, addressing the
input compatibility problem described in upstream issue
[172](https://github.com/DigitalHolography/AngioEye/issues/172).

## Changes

- Accepts EyeFlow's `ProcessingMoments` and `ProcessingBandRatio` roots as well
  as the older `Processing` and `ProcessingAlt` layout. Batches can contain both
  layouts; the selected method is kept consistent across acquisitions.
- Reads current global per-beat waveform paths, retaining raw and filtered
  representations separately. Exported metrics, values, units and axes remain
  unchanged. Original EyeFlow files are opened read-only.
- Uses clear GUI method labels: **Doppler moments** and **Frequency-band ratio**.
  Existing CLI names and saved method preferences remain supported.
- Records the actual source group and method in each analysis file and manifest.
  Reports ambiguous groups and conflicting method metadata instead of silently
  selecting a different method.
- Retains existing blood-volume-rate (BVR) exports and lists their dataset paths
  in the metrics manifest. No new BVR calculation is introduced.

## Installation and use

Download and run **AngioEye-v1.24.1.exe**. This is a standalone Windows x64
application: Python and its dependencies are bundled, and installation is not
required. First launch extracts the bundled runtime and may take a moment.
This is an unsigned community build.

Select the existing `.holo` recordings or their containing folder. The matching
`<recording>/<recording>_EF/h5/<recording>_EF.h5` exports must be present. In the
advanced Run view, select the EyeFlow method. Use separate output folders when
running the two methods to keep both sets of results.

## Validation and limits

Validation performed for this build: all 150 regression tests passed, along
with Ruff lint and formatting checks. The packaged Windows executable passed
end-to-end tests on synthetic legacy and EyeFlow v1.22-schema acquisitions,
covering both methods, all four CLI branch names, HTML summaries, metrics
manifests, exported values and unchanged source-file hashes. SHA-256 checksums
and build dependency versions accompany the executable. The executable was
built and tested locally using `build_installer.ps1 -Standalone` and
`test/frozen_smoke.py`; this release does not depend on GitHub Actions.

The new-schema fixtures follow EyeFlow v1.22.0 commit
`b1a5063e69a21d65c3492ef16d8634bf20bba4b9`. Real newly processed study files have
not yet been supplied for validation. Reading both schemas does not establish
numerical equivalence between EyeFlow versions or validate research conclusions.
EyeFlow v1.22 waveform metrics use filtered signals upstream; the adapter
preserves those exported metrics without recalculating them.
